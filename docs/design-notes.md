# 视觉与复刻笔记

本文记录复刻版从「参考产品的信息架构」到「可运行界面」的设计取舍。它不是设计系统规范，而是一份便于后来者继续修改的实现说明。

## 1. 复刻目标

复刻版追求三件事：

1. **信息架构一致**：导航分组、页面层级、地址形态尽量贴近参考产品，让熟悉该产品的人能快速找到入口。
2. **视觉语言接近**：主色、布局比例、表格密度、状态色和卡片阴影保持同一类后台产品的观感。
3. **工程实现独立**：不使用源站代码、接口、图片、字体或图标包；所有布局和组件由 Vue 3 + Element Plus 重新实现。

不追求：

- 像素级一比一还原；
- 完整业务功能对等；
- 复制源站的品牌标识与素材。

> 仓库不包含参考产品的任何截图。所有图形由 CSS、Element Plus 图标和 ECharts 生成，演示数据为虚构内容。

## 2. 从参考产品抽象出的结构

参考产品最显著的特征不是某个页面，而是「双层导航 + 高密度表格」：

```text
┌──────────────────────────────────────────────────────────┐
│ Logo   线索管理  客户管理  订单管理  系统设置  统计报表 ... │ 48px
├──────────┬───────────────────────────────────────────────┤
│ 侧栏      │ 系统公告                                       │ 36px
│ 当前模块  ├───────────────────────────────────────────────┤
│ 的子菜单  │ 页面标题                                       │
│          │ 筛选卡片                                       │
│          │ 操作栏 + 表格 + 分页                            │
└──────────┴───────────────────────────────────────────────┘
```

关键观察与对应实现：

| 观察 | 实现 |
| --- | --- |
| 顶部按业务域分段，点击后切换整个侧栏 | `youmiNavSections` 同时描述顶部区块和侧栏条目 |
| 侧栏只显示当前业务域，减少层级噪声 | `findSectionByPath()` 根据路径匹配区块 |
| 页面顶部有筛选卡片，条件较多时自动换行 | `.ym-filter-card` + `.ym-filter-row` 使用 flex-wrap |
| 表格行高紧凑、表头浅灰、操作列靠右 | 统一覆盖 Element Plus 表格样式 |
| 状态用彩色标签表达，按钮以文字链接为主 | `YM_ORDER_STATUSES` 等常量集中管理标签与颜色 |
| 公告条常驻内容区顶部 | 36px 公告条，4.5 秒轮播，可关闭 |
| 侧栏底部显示版本号 | `版本 1.8.6.1` 文本 |

## 3. 视觉令牌

主色与基础色定义在 `frontend/src/styles/youmi.scss`：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 主色 | `#035cff` | 按钮、选中态、链接、图表柱 |
| 主色深阶 | `#0249cc` | hover / active |
| 主色浅底 | `#e8f0ff` | 浅色选中背景 |
| 侧栏背景 | `#001529` | 深色业务侧栏 |
| 侧栏 hover | `#0a2545` | 条目悬停 |
| 页面背景 | `#f5f6f9` | 内容区底色 |
| 卡片背景 | `#fff` | 筛选卡、表格面板 |
| 主文本 | `#222` / `#303133` | 标题与正文 |
| 次文本 | `#606266` | 表格内容、表单标签 |
| 弱文本 | `#909399` | 辅助信息 |
| 危险/提醒 | `#f56c6c` / `#f08a5d` | 必填星号、空状态提示 |
| 圆角 | `4px` | 按钮、输入框；标签为 `2px` |
| 卡片阴影 | `0 4px 12px rgb(0 0 0 / 12%)` | 筛选卡与内容面板 |

字体使用系统字体栈：

```css
font-family: "Microsoft YaHei", "微软雅黑", "Helvetica Neue", Arial, sans-serif;
font-size: 14px;
```

不引入 Web Font，避免额外请求和字体授权问题；这也意味着不同操作系统下的字形会有细微差异。

## 4. 布局实现

| 区域 | 尺寸 / 行为 |
| --- | --- |
| 顶栏 | 固定，高 48px，白底，底部 1px 阴影 |
| Logo | 180px 宽，纯 CSS 文本标识（「友米」色块 + `·` + `SCRM`） |
| 顶部导航 | 七项，图标 + 文案，选中项显示 2px 主色下划线 |
| 侧栏 | 固定，顶部从 48px 开始，宽 180px，深色背景 |
| 侧栏条目 | 高 48px，选中项主色填充 |
| 内容区 | `padding: 48px 20px 20px 200px`，即让出顶栏和侧栏 |
| 公告条 | 高 36px，浅蓝底，轮播 + 圆点 + 关闭 |
| 响应式 | 1280px 以下缩小顶栏字号和内边距，侧栏 170px |

布局没有使用 Element Plus 的 `el-menu`，而是用原生按钮 + 自定义样式。原因是参考产品的顶部导航是「业务域切换器」，不是标准多级菜单；用 `el-menu` 反而要覆盖大量默认行为。

路由切换使用 140ms 透明度过渡。侧栏高亮规则：

```ts
if (route.path === path) return true;
if (path === "/crm/clues/create") return false; // 一次性入口不继承高亮
return route.path.startsWith(`${path}/`);
```

## 5. 页面模板

### 5.1 列表页

以订单列表为例，页面由四段组成：

```text
页面标题
筛选卡片  关键词 / 状态 / 负责人 / 日期      查询 重置
面板头    标题                         新建 导出 批量操作
表格 + 分页
```

实现约定：

- 筛选项在 `query` 响应式对象中维护，点击「查询」重置页码后请求。
- 点击「重置」恢复默认值并立即查询。
- 删除、审核等破坏性操作使用 `ElMessageBox.confirm` 二次确认。
- 空数据不隐藏表头，保持页面结构稳定。
- 分页固定右对齐，页大小切换后回到第一页。

### 5.2 详情与编辑

- 轻量编辑使用 `el-dialog`，复杂详情使用 `el-drawer`。
- 客户详情抽屉按「基本信息 / 标签 / 跟进 / 商机 / 订单」分区。
- 表单校验集中在组件内，提交失败保留用户输入。
- 金额输入使用 `el-input-number`，提交前转为数值。

### 5.3 状态标签

状态与颜色集中在 `frontend/src/youmi/constants.ts`：

| 状态 | 文案 | 标签类型 |
| --- | --- | --- |
| 订单 1 | 待审核 | warning |
| 订单 2 | 已确认 | primary |
| 订单 3 | 已完成 | success |
| 订单 4 | 已取消 | info |
| 客户 1 | 潜在客户 | info |
| 客户 2 | 跟进中 | primary |
| 客户 3 | 已成交 | success |
| 客户 4 | 已流失 | danger |

新增状态时只改这一处，避免页面里散落魔法数字。

## 6. 报表页设计

### 6.1 员工业绩

结构：

```text
日期范围 + 部门 + 员工 + 查询/重置/导出
5 张统计卡
成交金额 Top 8 柱状图
员工明细表
```

- 默认区间为最近 7 天（含今天）。
- 日期、部门、员工变化时重新请求或重绘图表。
- 部门与员工筛选是**前端过滤**：后端只按日期返回全部员工，前端再按 `deptName`、`userName` 过滤。
- 统计卡与图表都基于过滤后的结果，导出的 CSV 也使用同一份数据。
- 图表使用 ECharts 6 的按需引入，窗口 resize 时调用 `chart.resize()`。

统计卡中的「新增客户」实际是员工名下客户总数，卡片脚注写明「名下客户总数」。这是一个已知口径偏差，保留界面文案是为了贴近参考产品的信息密度，真实统计应以脚注和接口文档为准。

### 6.2 员工绩效

用两个子标签组织：

- **签收绩效**：客户数、跟进数、订单数、金额，按固定权重合成演示评分；
- **线索转化绩效**：订单数、成交率、客单价等派生指标。

页面没有额外接口，全部基于员工业绩数据计算。派生公式集中在页面内，便于替换为真实规则。

### 6.3 CSV 导出

- 纯前端生成，使用 `Blob` + `URL.createObjectURL`。
- 内容以 UTF-8 BOM (`\uFEFF`) 开头，保证 Excel 打开中文不乱码。
- 字段统一加双引号，内部双引号转义为 `""`。
- 导出文件名包含日期区间或页面名称。

## 7. 业务语言映射

参考产品的「线索 / 客户 / 订单」与本项目的「客户 / 合同」不是同一套模型。复刻版通过状态映射保持界面语义：

| 界面概念 | 数据 | 规则 |
| --- | --- | --- |
| 线索 | `biz_customer` | `status = 1` |
| 客户 | `biz_customer` | `status IN (2, 3)` |
| 转为客户 | 更新状态 | `1 -> 2` |
| 订单 | `biz_contract` | 合同即订单 |
| 待审核 | `biz_contract.status` | `1` |
| 审核通过 | 更新状态 | `1 -> 2` |
| 订单完成 | 更新状态 | `2 -> 3` |
| 客户编码 | `biz_customer.id` | 前端补零为 `C000001` |

映射层只存在于前端筛选参数和少量后端查询中，没有为了复刻去改数据库表名。这样做的好处是通用 SCRM 与复刻版可以共享同一套业务模块；代价是术语会在代码层残留（例如接口仍叫 `contracts`）。

## 8. 占位页策略

参考产品有大量入口（加粉、打单发货、质检、云仓等），完整实现不现实。复刻版的处理：

- 保留导航条目和路由，保证信息架构完整；
- 统一渲染 `PlaceholderPage`，提示「当前账号暂无查看权限，或该模块尚未配置」；
- 不伪造按钮、不假装有数据、不拦截真实操作。

这是有意的取舍：宁可明确「尚未实现」，也不做看起来能用、实际无行为的假交互。唯一例外是云店管理页，它展示了平台卡片和授权说明，但没有真实授权能力。

## 9. 与原产品的有意差异

| 项目 | 参考产品 | 复刻版 | 原因 |
| --- | --- | --- | --- |
| Logo | 品牌图形 | CSS 文本标识 | 不使用品牌素材 |
| 图标 | 自有图标体系 | Element Plus Icons | 避免复制资源 |
| 字体 | 可能使用定制字体 | 系统中文字体 | 授权与体积 |
| 导航 | 可能由权限动态下发 | 静态路由 | 降低实现复杂度 |
| 数据 | 真实业务数据 | 虚构演示数据 | 隐私与合规 |
| 未实现模块 | 完整功能 | 统一占位页 | 控制范围 |
| 页面密度 | 依产品版本变化 | 固定 14px / 46px 行高 | 保持一致性 |

## 10. 可访问性与性能

已做的：

- 所有可点击元素使用 `<button>` 或 Element Plus 组件，保留键盘焦点。
- 图标按钮配 `el-tooltip` 文案。
- 颜色不是唯一信息载体，状态同时有文字。
- 路由懒加载，报表页按需初始化 ECharts。
- 图表在组件卸载时销毁，定时器在 `onBeforeUnmount` 清理。

尚未做的：

- 未做完整的键盘导航与屏幕阅读器测试。
- 未适配移动端；1280px 以下仅做轻度收缩，窄屏会出现横向滚动。
- 未做暗色主题。
- 未做国际化，文案全部为简体中文。

## 11. 后续可以改进的地方

1. 用 CSS 变量收敛颜色和间距，支持主题切换。
2. 抽出 `FilterCard`、`DataPanel`、`StatusTag` 等通用组件，减少页面重复。
3. 把部门/员工筛选移到后端，避免大数据量下的前端过滤。
4. 为表格增加列设置、密度切换和导出范围选择。
5. 补充空状态插图与错误状态页，但继续使用原创图形。
6. 在保持信息架构的前提下，重新设计一套不依赖参考产品品牌元素的视觉识别。
